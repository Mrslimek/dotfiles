# systemd-boot конфигурация

Этот пакет **НЕ управляется через stow**. Здесь хранится только каноничная
версия `loader.conf`, потому что файл живёт в ESP (EFI System Partition),
которая отформатирована в **FAT32**, а FAT32 не поддерживает симлинки.

## Структура

```
systemd-boot/
├── README.md       ← этот файл
└── loader.conf     ← каноничная версия (копия того, что в /boot/loader/)
```

## Синхронизация

### Из dotfiles → в систему (применить изменения)

Если меняешь `loader.conf` здесь в репо, скопируй его в ESP:

```bash
sudo cp ~/dotfiles/systemd-boot/loader.conf /boot/loader/loader.conf
```

Изменения вступают в силу при следующей загрузке — пересобирать UKI не нужно.

### Из системы → в dotfiles (зафиксировать изменения)

Если менял `loader.conf` напрямую в `/boot/loader/` (или через `bootctl`),
зафиксируй изменения в репо:

```bash
cp /boot/loader/loader.conf ~/dotfiles/systemd-boot/loader.conf
```

## Что внутри

`loader.conf` управляет поведением systemd-boot:
- `timeout 0` — меню скрыто, показывается по нажатию **Space** во время загрузки
- `console-mode` — режим консоли (закомментирован = авто)

## Почему так, а не через stow

Варианты рассмотреть и отвергнуть:
- **Симлинк** — невозможен, FAT32 не поддерживает
- **bind-mount через fstab** — работает, но добавляет точку отказа при загрузке
  (если dotfiles-репозиторий недоступен, /boot не смонтируется корректно)
- **Копия + ручная синхронизация** — выбранный подход. Простой, прозрачный,
  риск drift минимальный (файл маленький, меняется редко)
