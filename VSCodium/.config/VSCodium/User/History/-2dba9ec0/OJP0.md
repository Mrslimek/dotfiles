# API Share-Link для фронтенда

## Обзор

Share-Link API предоставляет возможность создавать анонимные ссылки для доступа к сущностям и их аффиксам без аутентификации.

---

## Эндпоинты

### 1. Создать share-линк

**POST** `/share-link/create`

Создает анонимную ссылку для доступа к сущности.

**Заголовки:**
- `Session-Token` (обязательный) - токен сессии аутентифицированного пользователя
- `Partition-Uuid` (обязательный) - UUID партиции сущности
- `Content-Type: application/json`

**Тело запроса:**
```json
{
  "url": "https://w54.p3.54origins.com/share/",
  "entity_uuid": "56c5fd1d-65af-4fe9-b1a2-d8210c870468",
  "expires_at": "2025-12-31T23:59:59Z"
}
```

**Параметры:**
- `url` (обязательный) - базовый URL для share-линка
- `entity_uuid` (обязательный) - UUID сущности для которой создается ссылка
- `expires_at` (обязательный) - дата и время истечения ссылки в формате ISO 8601

**Ответ (200 OK):**
```json
{
  "url": "https://w54.p3.54origins.com/share/abc123...",
  "token": "abc123...",
  "entity_uuid": "56c5fd1d-65af-4fe9-b1a2-d8210c870468",
  "partition_uuid": "bb260a18-36b2-4b42-b424-841a712edcac",
  "expires_at": "2025-12-31T23:59:59Z"
}
```

**Ошибки:**
- `400` - отсутствует заголовок `Partition-Uuid`
- `401` - отсутствует или неверный `Session-Token`
- `404` - сущность или партиция не найдена
- `422` - неверный формат данных

**Нюансы:**
- Дата истечения должна быть в будущем и не позднее чем через 2 года от текущего момента
- Ссылка привязана к конкретной сущности и партиции

---

### 2. Получить список share-линков

**GET** `/share-link/list?entity_uuid=<uuid>`

Возвращает все share-линки для конкретной сущности.

**Заголовки:**
- `Session-Token` (обязательный) - токен сессии аутентифицированного пользователя

**Query параметры:**
- `entity_uuid` (обязательный) - UUID сущности для получения списка ссылок

**Ответ (200 OK):**
```json
{
  "count": 1,
  "links": [
    {
      "uuid": "123e4567-e89b-12d3-a456-426614174000",
      "url": "https://w54.p3.54origins.com/share/",
      "token": "abc123...",
      "full_url": "https://w54.p3.54origins.com/share/abc123...",
      "entity_uuid": "56c5fd1d-65af-4fe9-b1a2-d8210c870468",
      "partition_uuid": "bb260a18-36b2-4b42-b424-841a712edcac",
      "expires_at": "2025-12-31T23:59:59Z",
      "created": "2024-11-26T13:25:32.612943",
      "created_by": "76715295-e362-4623-8efc-929ea661d5e9",
      "is_expired": false
    }
  ]
}
```

**Ошибки:**
- `401` - отсутствует или неверный `Session-Token`
- `400` - неверный формат `entity_uuid`

### 3. Получить сущность через share-линк

**GET** `/share-link/entity`

Позволяет получить данные сущности по share-линку без аутентификации.

**Заголовки:**
- `Share-Token` (обязательный) - токен share-линка

**Ответ (200 OK):**
```json
{
  "partition": "project_management",
  "uuid": "56c5fd1d-65af-4fe9-b1a2-d8210c870468",
  "created": "2024-11-26T13:25:32.612943",
  "modified": "2024-11-26T13:25:32.612943",
  "entity_type": "project",
  "actor": "76715295-e362-4623-8efc-929ea661d5e9",
  "parent": "a0267432-4cb1-4eb5-af99-9eb7c4aed496",
  "params": {
    "name": "Project 1"
  },
  "owner": "08ee8342-0b22-4611-86c6-1f7947884eee",
  "uinfo": {
    "email": "example@mail.ru",
    "first_name": "John",
    "last_name": "Doe",
    "groups": ["d0d53af4-eb05-4e1c-95f1-935ff453dc37"]
  },
  "owner_uinfo": {
    "service_name": "SERVICE_NAME",
    "service_domain": "SERVICE_DOMAIN"
  },
  "files": []
}
```

**Ошибки:**
- `403` - отсутствует заголовок `Share-Token`
- `410` - ссылка не найдена или истекла
- `403` - неверный формат токена

**Нюансы:**
- Share-токен извлекается из URL при переходе по ссылке
- Данные сущности возвращаются в том же формате, что и при обычном запросе

### 4. Получить список аффиксов через share-линк

**POST** `/share-link/affix/list`

Возвращает список аффиксов (комментариев, timelog-записей и т.д.) для сущности, доступной по share-линку.

**Заголовки:**
- `Share-Token` (обязательный) - токен share-линка
- `Content-Type: application/json`

**Тело запроса:**
```json
{
  "affix_type": "comment",
  "limit": 10,
  "offset": 0,
  "order": "desc",
  "order_by": "created"
}
```

**Параметры:**
- `affix_type` (опциональный) - тип аффикса для фильтрации (например, "comment", "historyOfIdeaChanges")
- `limit` (опциональный) - количество возвращаемых записей (по умолчанию 25)
- `offset` (опциональный) - пропустить первые N записей
- `order` (опциональный) - порядок сортировки: "asc" или "desc"
- `order_by` (опциональный) - поле для сортировки (например, "created", "modified", "affix_type")
- `order_by_params` (опциональный) - сортировка по параметрам
- `depth` (опциональный) - глубина поиска
- `entity_type__not` (опциональный) - исключить типы сущностей
- `owner` (опциональный) - UUID владельца или список владельцев
- `owner__not` (опциональный) - исключить владельцев
- `params` (опциональный) - фильтр по параметрам аффикса
- `actor` (опциональный) - UUID актора или список акторов
- фильтры по дате: `created__lte`, `created__gte`, `created__lt`, `created__gt`, `modified__lte`, `modified__gte`, `modified__lt`, `modified__gt`

**Ответ (200 OK):**
```json
{
  "affix_uuids": ["uuid1", "uuid2", ...],
  "total": 2
}
```

**Ошибки:**
- `403` - отсутствует заголовок `Share-Token`
- `410` - ссылка не найдена или истекла
- `403` - неверный формат токена
- `400` - ошибка валидации параметров

**Нюансы:**
- `entity_uuid` берется из share-токена, его не нужно передавать в запросе
- Возвращается только список UUID аффиксов, для получения полных данных используйте эндпоинт чтения

### 5. Прочитать аффиксы через share-линк

**POST** `/share-link/affix/read`

Позволяет получить полные данные аффиксов по их UUID.

**Заголовки:**
- `Share-Token` (обязательный) - токен share-линка
- `Content-Type: application/json`

**Тело запроса:**
```json
{
  "affix_uuids": ["uuid1", "uuid2"],
  "with_files": false
}
```

**Параметры:**
- `affix_uuid` (опциональный) - UUID одного аффикса
- `affix_uuids` (опциональный) - список UUID аффиксов
- `with_files` (опциональный) - включить файлы аффиксов в ответ
- `fields` (опциональный) - список полей для частичного чтения
- `params_fields` (опциональный) - параметры для частичного чтения

**Важно:** Должен быть указан либо `affix_uuid`, либо `affix_uuids`.

**Ответ (200 OK):**
```json
[
  {
    "uuid": "affix-uuid",
    "created": "2024-11-26T13:25:32.612943",
    "modified": "2024-11-26T13:25:32.612943",
    "affix_type": "comment",
    "actor_uuid": "76715295-e362-4623-8efc-929ea661d5e9",
    "entity_uuid": "entity-uuid",
    "params": {},
    "files": []
  }
]
```

**Ошибки:**
- `403` - отсутствует заголовок `Share-Token`
- `410` - ссылка не найдена или истекла
- `403` - неверный формат токена
- `422` - не указан `affix_uuid` или `affix_uuids`
- `403` - один или несколько аффиксов не принадлежат сущности из share-линка

**Нюансы:**
- Все запрошенные аффиксы должны принадлежать сущности, для которой был создан share-линк
- Проверка принадлежности выполняется на уровне базы данных для безопасности
- Можно читать как один аффикс через `affix_uuid`, так и несколько через `affix_uuids`

## Общие замечания

1. **Share-Token заголовок:** Все эндпоинты для анонимного доступа требуют заголовок `Share-Token`.

2. **Истечение ссылок:** Share-линки имеют дату истечения. После истечения ссылки возвращают ошибку `410 Gone`.

3. **Валидация UUID:** Все UUID должны быть валидными UUID4 строками.

4. **Формат даты:** Все даты должны быть в формате ISO 8601 (например, `2025-12-31T23:59:59Z`).

5. **Пагинация:** Для больших списков используйте параметры `limit` и `offset` для постраничной навигации.

6. **Фильтрация:** Эндпоинты списка аффиксов поддерживают множество параметров фильтрации и сортировки.

7. **Коды ошибок:** API использует стандартные HTTP коды:
   - `200` - успех
   - `400` - ошибка валидации данных
   - `401` - ошибка аутентификации
   - `403` - доступ запрещен
   - `404` - ресурс не найден
   - `410` - ресурс недоступен (ссылка истекла)
   - `422` - необрабатываемая сущность (ошибка валидации)
